# 04-admin-bootstrap: ADMIN_PHONES warning and the admin bootstrap model

**Verdict: FIX FIRST, 3/10.** The warning works as coded, but it protects a model where admin = "first person to type the number". The two-admin rule and the A45 exemption inherit that hole.

## What I ran
- `node review/repro/04-takeover.js`: spawns the real server (PORT 8104, ADMIN_PHONES=`01711000000,+12125550123`) and runs the attack over HTTP.
- `node review/repro/04-edge.js`: in-process `handleApi` with a memory store. Covers ADMINS() parsing under NODE_ENV=production, duplicates, chphone/delete, revocation, adminCount, and the A45 exemption.
- Read lib/handler.js, api/index.js, core.js (inbox, review/confirm, users, publicUser).

## Findings
| ID | Sev | Finding | Evidence | Fix |
|---|---|---|---|---|
| F1 | **Critical** CONFIRMED | Sign-up has no phone verification. Anyone who knows an admin number can register it first and become admin. With both numbers, the attacker holds both admin seats, so the "second admin must approve" rule becomes two accounts of one person. The real owner then gets `phone_taken`. Admin powers include settling markets, issuing `resetpw` codes, reading feedback and disputes, and editing site settings. | 04-takeover.js: `attacker signup admin#1: 200, me.admin = true`, `admin#2 ... me.admin = true`, `real owner signup: 400 phone_taken`, `attacker admin#2 issues resetpw ... 200`. Admin numbers are in docs and README, and `+1212555...` examples are guessable. | Do not grant admin on signup. Use a separate `ADMIN_SETUP_SECRET` (or per-number one-time claim code) that the owner submits, or grant admin only after OTP verification of the number (lib/sms.js already exists). Short term: SK signs up both admins right after deploy and before any public URL is shared, and verifies it by checking `/api/users`. Document that as a launch gate. |
| F2 | High CONFIRMED | Second path: an admin who runs `chphone` or `delete` frees their admin number. The flag is dropped (chphone) or the account is wiped (delete), and the next person to sign up with that number is admin. A legitimate cleanup becomes a takeover window. | 04-edge.js: `admin chphone ... after chphone admin=false`, `attacker signs up freed admin number admin= true`, `re-signup of deleted admin number admin= true`. | handler.js chphone/delete: refuse for numbers in ADMINS(), or keep a tombstone so the number cannot be re-registered until an admin releases it. |
| F3 | High CONFIRMED | Removing a number from ADMIN_PHONES does not revoke admin. The flag is written once at sign-up. It is cleared only by chphone. docs/breach-response.md step 2 ("remove that number from ADMIN_PHONES and redeploy") does nothing for an existing session or account. | 04-edge.js: `number removed from ADMIN_PHONES, existing admin still admin= true`, `still opens inbox 200`. | Compute admin at read time, e.g. `isAdmin(uid)` = the phone for that uid is in ADMINS(). Do not store `u.admin`. That also fixes F2's drift. Fix the doc until then. |
| F4 | Medium CONFIRMED | A45: ADMIN_PHONES numbers skip the IP/phone-country block. Combined with F1, a blocked-country visitor who knows an admin number signs up and becomes admin. Alone it is only a bypass for people who already hold an admin number. | 04-takeover.js: signup with `x-vercel-ip-country: BD` returned 200 and admin. 04-edge.js: `A45 BD ip, admin number 200` vs `400 not_available` for a normal number. | Resolved by F1's fix. Optionally apply the exemption only when the number has a verified admin claim. |
| F5 | Medium CONFIRMED | The warning is bypassed by duplicates or aliases. `01711000000,+8801711000000` normalizes to the same number twice. `list.length` is 2, with no warning, and `adminCount` is 2. A single admin shows as two. | 04-edge.js: `dupes "01711000000,+8801711000000" length=2 warned=0`. Three aliases give length 3. | handler.js ADMINS(): `[...new Set(list)]` before counting, and optionally throw on duplicates in production. |
| F6 | Medium CONFIRMED | `adminCount` counts env numbers, not registered admins. With 2 env numbers and only 1 person signed up, the banner is hidden although no second admin can approve. The warning checks the config, not the capability it exists to protect. | 04-edge.js: `1 registered admin, 2 env numbers -> adminCount 2`. | In the inbox handler count `users.filter(admin && !deleted)`. |
| F7 | Low CONFIRMED | The warning fires once per process, once per cold start. Test: 1000 calls gave 1 warn. Under serverless, scale-out cold starts repeat it, so it is noise in the Vercel logs and no one is paged. The only user-visible signal is the banner, shown to admins who open #admin. | 04-edge.js: `warn count 1`. | Treat the warning as advisory. Put the count on the existing /api/health-style check or the ops checklist. Do not rely on logs. |
| F8 | Low CONFIRMED | `chphone` does `delete s.attempts[phone]`, but attempts are keyed by `tokHash('try:'+phone)`. It is a no-op and the failed-pin counter is never cleared there. It also clears nothing for `delete`. It is harmless but shows the code was not exercised. | handler.js lines 232 and 242, read against `limited()`/`clearAttempts()`. SUSPECTED impact: low. | Use `clearAttempts(s, phone)`. |
| F9 | Low CONFIRMED | `VERCEL_ENV=preview` with garbage ADMIN_PHONES returns `[]`: no throw, and everyone is a non-admin. This is intended for non-prod, but a preview deployment that is public can have its admin numbers claimed per F1. | 04-edge.js: `VERCEL_ENV=preview, ADMIN_PHONES=garbage []`. | Note in docs. |

## What actually holds up (tested)
- Fail-closed in production works for empty, whitespace, `,`, `abc`, `;` separators, missing `+`, and a short number: all throw. api/index.js calls ADMINS() at boot, which gives a 503 `boot` response rather than silent no-admin.
- A trailing comma or an empty element between commas is tolerated, with the valid numbers kept. That is acceptable.
- A non-admin cannot see `adminCount` or any admin number: `inbox` returns `403 forbidden` and `home` has no `adminCount`. No endpoint I found returns env numbers. `publicUser.admin` is exposed only to the user themselves.
- A non-admin who changes their phone to an admin number does not gain admin. The flag is set only at sign-up.
- The warn fires with `NODE_ENV=production` (and VERCEL_ENV=production), exactly once per process.
- Same-uid self-approval is blocked (`same_admin`). Only F1's two-accounts-for-two-numbers route bypasses it. I did not find a way for one non-attacker admin to approve their own change.

## Does this item matter?
The warning itself is cheap and correct enough. For a 10,000-player play-money game the real exposure is F1. The admin numbers are team phone numbers, which are semi-public. Whoever registers first owns settlement, can reset any player's password, and can read feedback and disputes. Play money limits the financial harm, but trust in settlement is the whole product, so this earns a fix before launch. The cheapest sufficient fix is a launch-day checklist step (SK signs up both admins before sharing the URL), but it should be backed by computing admin from ADMIN_PHONES at read time (F3) and blocking chphone/delete for admin numbers (F2).
